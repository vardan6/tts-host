Problem: the Win32 handlers decide which of Revert, Delete previous, Remove superseded, Remove…, Verify, and Update apply by walking the raw scan. That code can only run on Windows and has no tests, and review follow-ups #6–#7 (damaged rows, tier precedence) were fixed there.

Solution: each ModelListRow carries its available actions and the package each one acts on. Settings only enables, labels, and dispatches.

  • Locality: tier and damaged rules in one module
  • Rules tested on Linux through model_list_tests
  • Settings menu code shrinks to rendering
  • Leverage: macOS and Linux UIs reuse it
Fits ADR 0007: native UI per platform wants the rules outside the Win32 module.

Problem: the rules for replace vs. queue, cancelling a warm-up load, idle unload, and reloading after a profile change live in a class inside main.cpp. No test reaches them.

Solution: a speech queue module with a small interface, with synthesis behind a seam. There are two adapters: the real runners and the stub runner.

  • Queue rules testable with stub runner
  • Two adapters justify the seam
  • main.cpp shrinks to wiring
  • Leverage: played-text history lands here

Problem: the chain language → profile → model → fallback lives in main.cpp and is tested only through CLI CMake scripts. load_eager picks profiles and reads idle overrides on its own, and two selection structs are copied field by field.

Solution: one module turns a request plus config into a selection and its remaining fallback, and the eager pick moves there too.

  • Fallback rules tested without processes
  • Delete one duplicate selection struct
  • Leverage: per-model options slice lands here

Worth exploring in-process

Problem: callers walk the JSON tree by key name and repeat the defaults, so the config module's interface ends up as wide as its schema.

Solution: the config module exposes typed reads for profiles, registry, and audio, and keeps key names and defaults inside.

  • Locality: one home per key
  • Interface shrinks; defaults stop leaking
ADR 0004 (JSON canonical config) still holds: the file stays JSON, and only the in-process interface changes.
